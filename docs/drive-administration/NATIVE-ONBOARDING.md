# Native selected-folder onboarding contract

Native onboarding design · 10 October 2026 · owned-fixture core and test-only visual handoff; native product access remains gated

## Decision

Build an **export-only, macOS-first native reader** before connecting the catalogue to a service. A person chooses one project folder, sees the exact read-only scope, requests a bounded metadata observation, reviews its limits, and can explicitly save metadata in the reader's private app container. A primary “Review in catalogue” action sends only the bounded snapshot bytes to a bundled catalogue pane; its existing untrusted import preview remains mandatory. A separate Reveal in Finder action is a fallback, not the main product handoff.

The isolated Phase A implementation scope is smaller: a native Swift core with a descriptor-relative Darwin walker, a controller and injected owned-fixture admission/lifecycle ports, tested only on fresh owned macOS fixtures. Python remains a reference/oracle, not part of the native runtime. The core must not ship a live picker or accept arbitrary command-line, HTTP or JSON paths. AppKit/WebKit wiring, signed sandbox and representative-volume work need later reviewed gates. This document is a proposal, not evidence that those components exist.

Keep snapshot and catalogue v1 unchanged. The first bridge is useful without pretending to solve physical-drive identity: it can produce actual selected-folder metadata for today's saved-location catalogue, while the user labels the drive/folder and searches that historical record offline. It will not automatically identify a reconnected disk or replace an older record.

## Why this route

1. **Native source access:** App Sandbox with user-selected read-only access and one directory-only `NSOpenPanel` supplies an actual platform boundary, once entitlements and behaviour are verified. Picker intent must never be replaced by an arbitrary browser or imported path.
2. **Same-process Swift reader:** use AppKit/Foundation for native UI and a small Darwin descriptor-relative walker for observation. Do not embed or spawn Python. Port the existing observer's explicitly bounded semantics, with differential/golden fixtures and independent review; changing languages does not transfer acceptance. No new general-purpose filesystem API is exposed.
3. **Container-only output:** the sandbox normally allows writes inside its own container. An explicit save may create a new snapshot there while source selections retain the read-only entitlement. Do not enable user-selected read-write, Downloads-wide write access or arbitrary Save As just to simplify export.
4. **One-way product handoff:** native UI owns Choose/Observe/Cancel/Save. A bundled, nonpersistent WebKit catalogue receives only validated v1 bytes as untrusted import data through a fixed structured-argument call. It has no native message handler, filesystem capability or operation API. No localhost service is needed. The handoff's new origin/navigation/generation controls require explicit owned tests before activation.

Official-source support and caveats are in `OFFICIAL-NATIVE-ROUTE-RESEARCH.md`. These are design inferences from documented primitives, not a tested packaging recipe.

## User journey and honest messages

1. **Choose a folder.** Explain that this stage records one project folder, not a whole drive. The app keeps no remembered source or default scan; the OS panel may retain its own navigation UI state. One native directory selection; Cancel has no application traversal or saved record. OS panel navigation itself is controlled by the OS and is not claimed to perform no metadata access.
2. **Review scope.** Show the selected path locally as inert text, the user's proposed label and fixed bounds. Native preflight may query the selected URL/held root and perform the narrowly necessary no-follow ancestor open/fstat identity checks. No ancestor enumeration, sibling reads, whole-volume survey or mounted-device enumeration. A folder label is not a drive ID. Broad system/home/volume-root selections and unsupported/ambiguous source classes must reject before descendant enumeration under a separately tested admission policy.
3. **Read folder metadata.** Explicit action consumes one selection. UI stays responsive, gives bounded progress and offers Cancel. No file-content hash, dependency analysis, backup operation or model/provider call. Five seconds is cooperative; an OS call can block beyond it.
4. **Review a snapshot.** Complete means within the selected folder's bounded policy at the claimed time, not a whole-drive or atomic survey. Partial shows every gap/stop reason. Failed, cancelled, revoked, root-changed and unsupported outcomes have no snapshot and must not become an empty record. A valid earlier catalogue is untouched.
5. **Review in catalogue.** The primary action opens the bundled catalogue pane directly and stages the v1 bytes in its same preview-before-add importer. The user sees the source label/date/partial gaps and chooses Add separate snapshot record or Cancel. No path hunting or extra grant is required. The importer still treats data as historical claims; adding creates a separate record with overview/search decisions. Temporary project selections are not saved in catalogue v1; embedded manual-plan export remains deferred. Native code reports “Sent for review”, not saved/added merely because delivery returned.
6. **Save catalogue in this app.** A native toolbar action requests a bounded data-only export of the complete edited catalogue, including labels and history, and saves a new generated file inside the app container. Verify the bytes and exact revision before acknowledging it. Native Open saved catalogue offers a straightforward list and staged replace/cancel. The view remains temporary until this save succeeds. Plaintext metadata retention is explicit; no source access is retained. The detailed return-data contract below is mandatory before claiming relaunch continuity.
7. **Optional snapshot file and Finder fallback.** An advanced native action may save just the reviewed snapshot under a generated unique container basename. Explain that it is one scan, not the combined catalogue. Save only validated bytes, verify before saying “Snapshot saved in this app”, and leave the preview intact on disk-full/write failure. There is no overwrite, pruning or automatic deletion. After a verified save, the user may request Finder reveal; report only “Reveal requested”. No Finder display, external copy or import is inferred. A future read always requires a fresh native picker and creates new history, never silently replacing an old record.

Source paths and native identifiers are not logged, sent to telemetry or placed in the output filename. No autosave, bookmark, credentials, background watcher, scheduling, network listener or persistent source permission is added. Explicitly saved metadata is persistence of the artifact, not persistence of access.

## Authority objects and proposed controller ports

The prototype interface below is a contract sketch, not a wire format or published API.

| Component | Receives | May return | Must not do |
| --- | --- | --- | --- |
| Picker/grant port | Explicit user choose intent and current generation | Live native grant owned by this process, or cancellation/unsupported | Accept JSON, strings or descriptor numbers as a grant; remember/reopen paths |
| Selected-root admission | Live native grant | Live native root lease, plus display-only native metadata | Enumerate siblings/mounts; follow aliases automatically; downgrade traversal checks |
| Observation controller | That exact live selection and generation | One bounded v1-compatible result from the native walker | Accept caller-supplied inventories; expose a general scan or arbitrary-path entry point |
| Preview model | Admitted v1 snapshot | Frozen presentation and explicit save intent | Acquire or retain filesystem capability |
| Container export port | Bounded validated bytes and one-use save intent | Verified new container-local artifact reference, or failure | Receive source paths/grants; overwrite, clean up previous files or write to source storage |
| Reveal port | Verified generated artifact reference and explicit reveal intent | Request acknowledgement only | Accept an arbitrary path from JSON/UI or imply import/copy success |

No serialised token recreates a selection. Platform hints do not enter the controller's authority path. The owned-fixture adapter can construct live native leases only from temporary directories the test itself created. Keep that constructor in the test target, not a production path-taking API. The production factory can be called only by the picker-owning native controller.

The native grant and selection have separate lifetimes. Closing a directory descriptor is not proof that all OS dynamic access was revoked. The ownership adapter explicitly adopts the implicitly started panel-origin scope described by Apple, does not double-start it, and stops that owned scope on every terminal branch. If another integration explicitly starts an additional scope, balance each successful owned start. Validate this ownership model on the supported native target rather than assuming descriptor close revokes kernel access. After the worker finalises, close every owned descriptor and end panel-scope ownership before any snapshot preview, export or WebKit delivery. Retain only immutable result bytes and retired session provenance. Scope-review Cancel also releases the adopted scope. No preview or save requires a live source lease. App cancellation immediately retires application-level authority and discards late results; it cannot promise instantaneous interruption of a blocked OS call. A fresh selection must not overlap an unfinished retiring observation. Process exit is the final cleanup boundary, not a promise of a five-second hard deadline.

## Native selected-root and traversal semantics

The Swift walker must implement and test this contract; none of these behaviours is claimed implemented by this document.

1. **Only native selection creates the root lease.** Configure one directory-only, single-selection panel with `resolvesAliases = false`, `canDownloadUbiquitousContents = false` and `canResolveUbiquitousConflicts = false`. Reject unsupported/cloud selections without attempting downloads or conflict resolution. These settings do not prove no OS-panel/provider metadata activity. Never accept an initial source from a CLI argument, environment variable, recent-path preference, dropped URL, web message or saved JSON. The returned file URL is not silently standardised, resolved through symlinks or expanded. Apply the existing bounded UTF-8/direct-absolute-path admission before opening it, including rejection of `/`, dot/dot-dot, repeated separators, controls and unsupported spelling. A native scope review displays the returned address before descendant reads. A native panel may itself navigate aliases; the application makes no claim to audit every OS-panel navigation.
2. **Pin the root with descriptors.** Port the component-by-component walk from `/`, using `openat` on one validated component at a time with `O_RDONLY | O_DIRECTORY | O_NOFOLLOW`, close-on-exec and `fstat`. Never enumerate ancestors. Hold the selected directory FD and its internal device/inode/fingerprint; no FD number or path becomes a public capability. Prove this works inside the selected-folder sandbox grant before native activation. If ancestor opening is denied, abstain rather than use a single path open that follows unchecked ancestors. Apple's archived [open manual](https://developer.apple.com/library/archive/documentation/System/Conceptual/ManPages_iPhoneOS/man2/open.2.html) documents the read-only/no-follow primitives; actual `openat` flags and SDK availability are verified only for the owned Phase A runner recorded below; signed sandbox admission remains a later gate.
3. **Require fresh address/object agreement.** Before any descendant enumeration, a separate no-follow re-walk must match the held root and the walker's root FD. Repeat at terminal admission. Compare identity while descriptors remain owned and pinned; never close/recycle a borrowed FD on cancellation. A root address/object replacement or detected root fingerprint change supplies no snapshot. Do not treat an absolute string, root label, URL, `st_dev` or UUID alone as agreement.
4. **Enumerate bounded names, then stat relative to the directory FD.** Use descriptor-owned directory iteration with exact close ownership. A successful `fdopendir` consumes its duplicated FD and `closedir` closes it; on failure, the caller closes that duplicate. Ensure `FD_CLOEXEC` on the iteration duplicate as well as every opened FD. Set errno to zero before each `readdir`; null plus zero is EOF, null plus nonzero is an error. Discard all gathered names on iteration error, mark that directory unreadable/disappeared and record one error. Never infer entry kind from `dirent.d_type`. Ignore only `.` and `..`. Gather at most 501 names; if a directory exceeds 500, record a directory-entry-limit gap and admit no arbitrary enumeration-order subset. Sort valid names by exact UTF-8 byte order, not locale or Swift canonical-equivalence ordering. Use `fstatat(parentFD, name, …, AT_SYMLINK_NOFOLLOW)`, the descriptor-relative equivalent of `lstat`, rather than `stat` or Foundation recursive enumerators on constructed absolute descendants. [Apple stat-family semantics](https://developer.apple.com/library/archive/documentation/System/Conceptual/ManPages_iPhoneOS/man2/lstat.2.html)
5. **Never open ordinary file contents.** Regular files contribute only nonnegative bounded logical `st_size` and status. Symlinks and special files are listed unsupported and never followed/opened/readlinked. Known placeholders, packages and unsupported source classes receive explicit exclusions, never hydration or silent traversal. Per-entry native metadata queries must not reintroduce path-following races; where a no-follow capability-safe query is unavailable, abstain for that classification rather than claim complete support.
6. **Check directory identity before and after descent.** Before descending, open the child relative to its held parent with the same no-follow directory flags. Its `fstat` fingerprint must match the preceding no-follow stat; otherwise do not enumerate it. On return, a changed child directory marks affected descendant observations stale and the snapshot partial. A changed selected root invalidates the entire result. Fingerprints are private race evidence, not content versions or durable identity.
7. **Do not cross the selected filesystem.** Compare child `st_dev` with the root before descent and compare the opened child descriptor again. A detected boundary is an unsupported entry plus gap. Root `fstatfs` may supply source-class metadata without a global mount listing. Equal device/filesystem IDs do not prove no bind/firmlink/mount alias or physical uniqueness; same-filesystem alias and post-admission directory movement remain explicit limitations. [Apple descriptor filesystem information](https://developer.apple.com/library/archive/documentation/System/Conceptual/ManPages_iPhoneOS/man2/fstatfs.2.html)
8. **Preserve names exactly or return no artifact.** Decode UTF-8 strictly; preserve raw Unicode scalar spelling and case. Use byte/data keys internally: Swift `String` equality is canonically equivalent and must not silently collapse different recorded spellings. Count v1 text limits by Unicode scalars, not grapheme clusters. Unrepresentable admitted observations, oversized paths, invalid sizes or an over-budget projection return no snapshot instead of silently omitting the offending metadata. [Swift string equality](https://docs.swift.org/swift-book/LanguageGuide/StringsAndCharacters.html)
9. **Bound work and terminal evidence.** Count the selected-root record in the 2,000-entry limit. Depth 0 is the root; at depth 8 record the directory and its depth-limit gap without enumerating children. Use an injected monotonic clock for five cooperative seconds from observation start; check cancellation/time between directory entries and before/after each OS-call boundary where control returns. Wall-clock UTC is only the claimed observation timestamp. Retain decimal-string byte/count fields and upfront canonical UTF-8 accounting before full JSON serialisation. No content hash, allocation/capacity estimate or previous-inventory reuse is introduced.
10. **Errors stay source-scoped and non-authoritative.** Root-open/guard errors produce failed/unsupported/root-changed outcomes with no snapshot. Descendant unreadable/disappeared/stale entries may produce partial inventory if root admission survives. Preserve explicit exclusion reasons and an error count in v1; native diagnostics may show bounded relative context but must not leak absolute paths into logs or exports. `complete` requires no gaps/errors/stop reason; it still is not atomic or whole-drive completeness.

### Exact Phase A observation parity

- Selection identity compares directory kind plus device/inode at selection and before/after observation. A metadata change while the scope is merely being reviewed establishes a fresh baseline when observation starts, provided address/object identity still agrees. Once observation starts, its root fingerprint must remain unchanged through terminal guard.
- Fingerprint is the exact tuple `(st_dev, st_ino, st_size, st_mtimespec.tv_sec, st_mtimespec.tv_nsec, st_ctimespec.tv_sec, st_ctimespec.tv_nsec, st_mode, st_nlink)`. Comparing seconds/nanoseconds separately avoids multiplication overflow while preserving Python nanosecond equality. Require nanoseconds in 0..<1_000_000_000 and checked native integer conversions; do not truncate seconds, full mode or link count. Selection identity and observation fingerprint have deliberately different roles.
- Keep a bounded private map keyed by the exact device/inode file-object pair when inode is nonzero (device zero remains valid). If observed aliases have conflicting fingerprints, or one file alias became stale after ancestor invalidation, mark all affected aliases stale and coverage partial. Do not deduplicate logical byte totals: they count paths, not independent storage or coherent content.
- Final entries sort by exact UTF-8 bytes of relative path (one root); gap summaries sort by exact reason bytes. This matches Python scalar order for well-formed UTF-8. No locale/canonical-equivalence sorting. A directory excluded at its 501st name is not required to inspect all remaining names; invalid *admitted* records reject projection, while excluded branches remain explicit gaps.
- `ENOENT` maps to `disappeared`; other returned filesystem errors map to `unreadable`, with one bounded error record per failed operation. Root open, root iteration, root stat or guard failure returns no snapshot; descendant failures can remain partial if terminal root admission passes. Child fstat failure retains the existing error behaviour; it must not silently certify descendants as complete. No automatic syscall retry for traversal errors. `readdir`/`fdopendir` errors are never EOF.
- Preserve exclusion strings: `depth_limit`, `directory_entry_limit`, `symlink_not_followed`, `special_not_followed`, `known_placeholder_marker`, `filesystem_boundary`, `changed_before_traversal`, `changed_during_traversal`, `root_or_ancestor_changed`. The default selection has no configurable name exclusions; unsupported native classification abstains at selection rather than inventing a complete record. Gaps are bounded to 2,000 occurrences and 32 unique reasons.
- The internal held lease permits exactly one controller ownership claim. A rejected claimant cannot observe, close or release another controller's borrowed descriptor. Serial and concurrent reuse are rejected; release is claimant-scoped and finalises before result admission.
- Admit the last progress/cancellation callback before the terminal root guard, then seal user callback admission. Afterwards check only internal latched cancellation/revocation/generation state; a callback cannot mutate the root after its final guard. Direct cancellation still applies during projection and final admission.
- Interruption latches the first walker stop reason; at each eligible check cancellation is tested before elapsed time. Stop reasons are `cancelled`, `time_limit`, `entry_limit`, `exclusion_limit` as in the reference. Controller terminal precedence is `revoked`, `root_changed`, `cancelled`, `unsupported`, `failed`, then `partial`/`observed`. Cancellation/revocation/root change and any projection failure return no artifact, regardless of collected rows. Exclusion overflow sets `exclusion_limit` and never silently drops evidence.
- Projected text rejects empty/whitespace-only values, C0, DEL/C1 and U+2028/U+2029; bounds use Unicode scalar count (label 240, path 1,024, timestamp 40, gap reason 120). Relative paths reject backslash, absolute form and empty/dot/dot-dot components other than the selected root `.`. UTF-8 decoding is fatal, never replacement decoding. Decimal strings are nonnegative canonical integers below 10^30. The admitted selected-root row must remain an observed directory. No extra schema fields are added.
- Observation time is frozen UTC with a valid v1 timestamp; scan ID is a bounded `scan_` plus 24 lower-case hex characters, source-scoped observation reference only. Cross-language comparisons normalise only generated scan IDs and observation times; all paths, kinds, statuses, logical sizes, coverage and gaps must agree. The hash identity of an absolute source path is not exported or treated as hardware identity.

No check above is a universal defence against a hostile concurrent writer or privileged remount. A directory already admitted and held by FD can be moved elsewhere before the next check. Preserve the existing limited pre-admission guarantees and post-read invalidation rather than claiming universal confinement or safety for adversarial user storage.

## Bundled catalogue handoff and save/reopen boundary

### Session-memory delivery, not persisted trust

After source descriptors and the adopted panel scope have been released, native code retains only the admitted immutable result, retired observation provenance, current view-session generation and a random one-use delivery ID in process memory. The controller authenticates the **origin of this transient delivery** by its own object ownership and current session/view state. No imported field, echoed nonce or JavaScript assertion can manufacture that provenance. It does not authenticate content versions, physical storage or the saved JSON artifact.

Bind delivery to one current `WKWebView`, its exact expected successfully loaded bundled main document and current main-frame navigation generation (a `file:` origin string alone is insufficient) and a versioned internal bridge contract (`catalogue-data-bridge/v1`, separate from the snapshot schema). On navigation, web-content-process termination, scan cancellation, replacement or view recreation, retire pending IDs and callbacks. A delivery ID is never a reusable bearer capability or persisted grant. Do not export it, accept it from a saved file or authorise a new read because JavaScript returns it.

Use a fixed `callAsyncJavaScript` function body and separately supplied arguments containing bounded JSON text and non-authoritative delivery metadata. No `evaluateJavaScript` string concatenation, template interpolation of filenames, HTML insertion or DOM manipulation that bypasses the importer. The current UI has no native ingress; a later reviewed refactor must share exactly the existing `C.parse` and preview/admission path between file import and snapshot-only host delivery. Enforce the 1 MiB snapshot limit and schema type before staging; native scan delivery cannot replace a whole catalogue. A busy or changed catalogue must reject/defer the staging operation rather than overwrite an edit. [Structured WebKit arguments](https://developer.apple.com/documentation/webkit/wkwebview/callasyncjavascript:arguments:inframe:incontentworld:completionhandler:)

Use separate observation, view-navigation and page-preview generations. Before superseding a staged host preview, issue a fixed host-to-page retirement call and wait for its matching acknowledgement before enabling replacement native work. The page retires the matching preview and Add closure without changing committed records. An Add processed before that retirement fence remains a valid prior historical addition; an Add processed after the fence rejects. If acknowledgement is lost or the view is unresponsive, block replacement work and require explicit view recovery; do not claim instantaneous cross-process cancellation. Cover delivery staged before its completion callback arrived.

An ingress in the page's JavaScript namespace runs in the expected page content world; using an isolated world does not automatically expose the IIFE's state. The ingress receives relative path strings as inert data, never absolute OS paths, source URLs, bookmarks, FDs, a grant or a native command endpoint. JSON remains untrusted through strict parsing, preview, explicit Add/Cancel, save and reopen. No `trusted`, `live_drive` or authenticated-content field is added. [WebKit content worlds](https://developer.apple.com/documentation/webkit/wkcontentworld)

### Bundle and resource policy

Construct the view with a nonpersistent website data store; load only a dedicated immutable frontend-assets subdirectory via `loadFileURL`, with that same narrow directory as `allowingReadAccessTo`. Never use `/`, a source folder, the app container or exports directory as the WebKit read root. Register **no** script-message handler or reply handler. Reject unapproved navigation, redirects, subframes, new windows, URL schemes, page uploads, file drops and Blob downloads; never forward rejected URLs to another app. Native UI replaces unsupported embedded-mode Open/Save controls so nothing appears to work while losing data. Existing Blob-based manual-plan export is explicitly unavailable in the first native host unless it receives its own reviewed data-only container-export path; it must not remain an apparently working button. Standalone manual planning remains unchanged.

Navigation checks alone do not block subresources. Retain the strict self-only scripts/styles and `default-src/connect-src 'none'` CSP, add a fixed network-blocking content rule before loading, and fail closed if rule installation fails. Do not grant network-client/server entitlement for this product stage. Verify resource denial and native sandbox behaviour independently; no one layer is represented as sufficient by itself. [Local bundle loading](https://developer.apple.com/documentation/webkit/wkwebview/loadfileurl(_:allowingreadaccessto:)), [website data stores](https://developer.apple.com/documentation/webkit/wkwebsitedatastore), [content rules](https://developer.apple.com/documentation/webkit/wkcontentruleliststore)

### Preserve the edited catalogue, not just the last scan

One-way scan delivery alone does not preserve user labels and multiple historical snapshot records. Catalogue v1 save/reopen does not persist temporary project selections. Hide or clearly disable embedded manual-plan export until its own reviewed container export exists; add no v1 field for selections. The product therefore needs this explicitly separate **native-initiated data-return contract** before claiming catalogue continuity:

- Native **Save catalogue** initiates one request to the known view; JavaScript cannot call a native save handler. A fixed trusted page function synchronously captures one immutable catalogue/revision, validates and budgets before serialisation, and returns a shallow fixed envelope of primitive strings. Envelope fields are bounded as well as the JSON. It returns bounded canonical catalogue JSON plus its captured revision, not a path/URL/filename or command. The host validates the bridge version, native request ID, current view/navigation/session and byte budget before accepting the result. Host memory is the authority; matching an untrusted echoed nonce alone is insufficient.
- Strictly validate returned catalogue data with the same admission contract, including duplicate keys, Unicode, schema version, 32 records/10,000 entries/4 MiB and nested snapshot bounds. If a native validator is used, prove parity against the unchanged JavaScript model; do not assume generic JSON decoding rejects duplicates. Include raw JSON limits of depth 12 and 150,000 value nodes, fatal Unicode, no numeric/Boolean values, duplicate keys including escaped-equivalent spelling, all hierarchy/gap rules and distinct raw/canonical budgets. Native code checks returned types/lengths before additional conversion/parsing. Invalid or oversized return data creates no output and leaves the view dirty. Post-return limits do not prevent WebKit allocating a result first; the trusted page must budget before returning. The API has no claimed hard execution deadline; hung/invalid callbacks retire without output. A data return does not authorise scanning any contained path.
- Save only to a generated, exclusively created app-container artifact, never a destination from JavaScript. Stage an owned pending file, verify exact written bytes, and publish it with a tested atomic no-replace operation before acknowledging the captured revision. Interrupted/pending files are never offered as completed catalogues; retain them rather than deleting unknown prior data. If the filesystem cannot support the required publish semantics, fail closed. If the user edited the catalogue while export was pending, report the saved earlier revision and retain the newer unsaved state. A stale callback cannot clear dirty state, overwrite or reveal another file. A fixed host-to-page saved acknowledgement names the captured revision and request/view generation; the page clears dirty state only if that exact immutable revision is still current. An echoed nonce is correlation data, not source authority.
- Native **Open saved catalogue** shows the app's own explicitly saved artifacts in a simple list, not a technical file hunt. List generated completed artifacts in bounded pages without eagerly parsing every file. Only after the user chooses one, read a bounded regular file with no-follow checks; treat its bytes as untrusted and stage the same existing replacement preview. Cancel retains the current catalogue. No automatic reopen on launch, deletion, pruning or legacy database migration.
- Standalone manual artifact import/export and a separately requested Finder reveal remain alternatives. Embedded-mode browser controls that cannot satisfy this contract are removed/replaced with native controls, with no silent fallback to arbitrary Save As.

Container saves/reopens use a pinned export-directory FD and generated single-component filenames with private creation modes, never imported label text. Verify regular-file/no-follow state through held FDs. Cap reads themselves independently of stat size, require EOF within budget and compare identity/size/mtime/ctime before and after. Treat growing/replaced/changed artifacts as failed untrusted reads and retain the current catalogue. Tests cover EINTR, partial writes/reads, full disk, name collisions and publication failure. Reconcile a published-but-unacknowledged generated file before any retry, with no automatic duplicate. Exact readback proves bytes observed now, not power-loss durability; no power-loss persistence promise is made by this slice.

Native Close/Quit consults the known view's dirty revision and in-flight state through a fixed data query. Offer Save/Discard/Cancel as appropriate, wait for an in-flight save or explicitly cancel its generation, and never report an unresponsive/failed view as safely saved. Existing browser `beforeunload` is not sufficient for native window or application termination. Discard is explicit and does not remove previously saved artifacts.

This controlled return adds a data flow from the view but no JavaScript-to-native invocation authority. It must be independently reviewed and tested; it is not already implemented. Native source access remains exclusively behind the native Choose/Observe actions.

## State transitions and cancellation

`idle → choosing → scope_review → observing → snapshot_review → saving → saved`

Every asynchronous action carries the current generation internally. Cancel, Close, newer selection, process restart or invalidation retires that generation. Stale callbacks cannot show a preview, save bytes, relabel a record or reveal a file. Repeated Observe and Save confirmations are one-use. No auto-retry of reads or writes after uncertain outcomes.

- Picker cancellation: back to idle; no application traversal.
- Rejected/preflight-unsupported scope: release resources; no result or fallback scan.
- Cancel/revoke/root change during observation: terminal no-snapshot outcome; close resources when the observing call finalises; show stopping until confirmed.
- Descendant error, known placeholder, depth/entry/directory/time limit: explicit partial result only if the root/selection remains admitted.
- Superseding selection while a worker is retiring: refuse or defer the new picker until the old work has released; never overlap scopes accidentally.
- Saving interrupted or outcome uncertain: preserve preview, do not claim save, and reconcile the one generated container artifact before another attempt. No overwrite-based retry.
- Quit/relaunch: no recovered grant, live source state or unsaved preview. Previously explicitly saved JSON requires explicit Open saved catalogue; no source grant is recovered. Dirty Close/Quit follows the explicit Save/Discard/Cancel contract above.

## Fixed budgets and source-class gate

Reuse the existing one-shot limits: 2,000 total entries, 500 per directory, depth 8, five cooperative seconds, no content hashing and no filesystem crossing. Preserve the 1 MiB snapshot bound and existing v1 path/text/decimal validation. Do not increase them to make a large external-drive demo look complete. The catalogue retains its independent 32-record/10,000-entry/4 MiB budget, with explicit rejection preserving prior state.

Native preflight must establish a tested supported-local-filesystem class without enumerating all volumes. Unknown classification is not “safe local”. A local-looking mount path or `volumeIsLocal` alone does not exclude cloud/file-provider behaviour. Existing `.icloud`/flag heuristics are deliberately incomplete. No network, virtual/provider-backed, package/library or unsupported filesystem traversal is enabled by this plan until its admission/exclusion policy is separately tested. Metadata-only means no intentional file-content read; it does not guarantee no OS metadata side effects, access-time updates or provider activity.

Reject source roots inside locations the app can already write (its own container/temporary export area) when claiming OS-enforced read-only source access. Test this using owned fixtures only. Static sandbox rights and dynamic selected-folder rights must be considered together.

## Identity and reconnection contract

The first native review may show nullable, source-scoped hints obtained from the selected root; they remain memory-only and are omitted from v1. Hardware identity and independent-copy count remain unknown.

| Situation | Required behaviour |
| --- | --- |
| Same label or current mount path | No match or merge inference |
| Equal volume UUID | At most a future reconciliation candidate; not physical identity or authentication |
| Missing UUID/unsupported native identifier | Unknown; do not generate a fake native ID |
| Two folders on one volume | Separate selected scopes and records; never collapse them |
| Renamed volume/mount alias | Fresh explicit selection; reject unsupported alias/symlink resolution, never normalise into access |
| Reused path, changed root handle/fingerprint | Withhold result under the existing root-change rules |
| Clone/reformat/restored image | Ambiguous or new identity; UUID equality cannot prove same hardware or independent media |
| Unplug/lock/unmount/denial | A failed current attempt, with historical catalogue retained; do not turn every error into “disconnected” |
| App restart or snapshot import | “Saved snapshot; current connection not checked”; no live or authenticated provenance |

Apple's persistent volume UUID hint differs from the explicitly non-restart-persistent `volumeIdentifier` and `fileResourceIdentifier`. Device/inode and held descriptors support bounded live checks, not durable drive identity. Do not add Disk Arbitration/IOKit serial probing, automatic mounting, a mount watcher or global disk inventory.

Persistent identity-assisted reconnect would require a later, separately reviewed versioned schema and UI. Store app record identity separately from platform/kind/time/value hints, preserve null/conflict states and explicit manual association. Reopened/imported hints remain historical claims; a saved hint never creates a grant. If a future bookmark feature is approved, read-only scope, stale resolution, no implicit mount and explicit reselect rules are separate acceptance requirements. No v1 extra field or trusted flag is allowed here.

## Implementation sequence and exit gates

### A. Owned macOS core tests first, only after this contract is reviewed

Phase A uses an explicitly injected owned-fixture source classification, never a production admission fallback. Reserve a new native Swift package/core and owned-fixture test target; preserve current Python/frontend runtime and v1 formats. No production picker, webview bridge, new HTTP route, persistent grant or default navigation is activated in this slice. Tests use injected grant/clock/identity/export seams; the raw owned-path fixture constructor exists only in the test target. macOS CI may compile and run the native descriptor walker against temporary directories it creates and owns. Linux/Windows jobs must not substitute a weaker implementation or count skipped Darwin tests as passes.

Use `macos-15` with explicit `DEVELOPER_DIR=/Applications/Xcode_16.4.app/Contents/Developer`, require Xcode 16.4 build 16F6 and macOS SDK 15.5, and record `swift --version`, OS and runner image identity before execution. Swift package tools version is 6.0 with an explicit language mode. Fail rather than silently selecting another Xcode if the pinned installation is unavailable. GitHub's [current runner image manifest](https://github.com/actions/runner-images/blob/main/images/macos/macos-15-Readme.md) lists this toolchain; the runner image itself remains mutable and its actual identity must be recorded. No local Swift compiler is installed in the assigned Linux workspace.

Cross-check native output against committed owned fixture expectations and the unchanged v1 parser, with normalisation limited to test-generated IDs/times. Python is an independently run test oracle, never a child holding a live source grant. Core tests cannot establish OS-panel or sandbox-grant acceptance.

### B. Signed native host and handoff probes, separately approved and owned-fixture-only

Validate the actual signed entitlement set, directory-only single-selection panel, cancellation, sandbox denial of writes to owned source fixtures and owned sibling/parent boundaries. Prove that the no-follow ancestor-opening algorithm works under the selected-folder grant; if it fails, stop rather than using realpath, weaker traversal or an unrestricted backend. Validate native grant lifetime and balanced ownership of security-scope calls. No persistent bookmark or permission transfer is introduced.

Validate the fixed one-way WebKit data ingress, bundle-only navigation/read access, nonpersistent store and explicit container saving. Test repeated/stale deliveries, UI edits and navigation between delivery/admission. Validate Finder fallback separately. Fill a supported filesystem/source-class matrix using owned test volumes. Actual native panel and sandbox probes need a suitable native execution environment; headless pure tests, ad-hoc signing or generic POSIX success alone cannot certify the packaged product or removable hardware.
### C. User-owned drive pilot, separate authorisation and environment gate

Only after B and independent review, confirm the intended connected user computer, exact non-critical selected project folder, supported filesystem and read-only purpose. Use the supported local executor route; no cloud scan of the user's computer. Check unexpected OS permissions before accepting them. No full-drive/system/home survey, real-source write probe, provider access, move/delete/restore or automatic refresh. A real external-drive, unplug/reconnect and native usability claim requires actual representative hardware evidence.

Windows needs a separate native traversal and permission design; current POSIX tests skip those operations. Linux portal grants can persist across sessions, so “no bookmark” is not sufficient for a no-persistence claim. Neither platform receives a weaker path-based fallback.

## Owned-fixture acceptance matrix

Phase A filesystem fixtures are created by the test under a fresh owned temporary root. Phase B source fixtures and adjacent sentinels are created by an external owned setup harness outside the app's inherent writable container/temp ranges; container output fixtures are separate. Test denial of both creating a new source child and changing an existing owned source file. Keep an adjacent owned sentinel as an out-of-scope witness; never use an existing user directory. Real mount/panel cases need explicitly prepared owned native fixtures and cannot be replaced by mock success.

| Native core builds with pinned macOS SDK/toolchain | Swift/Darwin target compiles; unsupported platforms abstain | A: owned macOS CI |

## Failure, budget and startup corrections

- First B-failure observations are exported separately from later finalisation
  observations. Raw process bytes are exported once with indexed metadata;
  later successful checks cannot erase the earlier refusal or partial listing.
  When no report packet exists, the bounded terminal still identifies the
  original error message and errno.
- A descriptor ledger preserves the initiating operation failure and bounded
  independent cleanup failures, attempts every owned close once and never
  retries an ambiguous descriptor number. Cleanup uncertainty remains failure.
- Work/finalisation checks propagate through the existing bounded filesystem
  algorithms and source bootstrap. Cooperative iterations cannot reset the
  absolute 720/900-second attempt budget. Cleanup remains available after
  expiry; no claim is made that a synchronous kernel call can be interrupted.
- Both fixed Python launches start through an explicit `/usr/bin/env -i`
  allowlist. Only required run/checkout/image identity fields and fixed
  interpreter settings reach bootstrap; the uploader receives only fixed
  settings, the bounded terminal and its run/source identity. Neither receives
  ambient credentials, proxies, startup hooks or inherited Python settings.

The trust boundary still assumes the reviewed checkout is not modified later by
another same-user process. Source pins are not OS isolation. The pinned artifact
uploader reopens pathname-based files after verification; the source does not
claim an immutable descriptor handoff into that external action. Missing output,
export/close uncertainty, upload failure or runner interruption cannot establish
acceptance. Terminal B evidence is historical data and cannot resume Stage C.
